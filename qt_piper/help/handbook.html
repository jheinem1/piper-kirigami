Piper Kirigami Handbook

Configure supported gaming mice through ratbagd, using a Qt 6 and KDE Kirigami interface. This handbook ships with the application and works offline.

Development preview: this is an experimental frontend based on Piper, not an official Piper release. Features depend on the device and its ratbagd driver. Real mouse behavior and firmware persistence still require testing on your hardware.

1. Getting started

  1. Connect a mouse supported by libratbag. The host needs a running ratbagd service that permits access to the device.
  2. Start Piper Kirigami and select the Device in the top toolbar.
  3. Select the on-device Profile whose settings you want to inspect or edit. Selecting a profile in this menu does not activate it on the mouse.
  4. Choose Buttons, Sensitivity, Lighting, Profiles or Advanced in the sidebar.
  5. Make changes, then use Apply when you are ready to send the edits covered by that page to ratbagd. See the scope explained below.

Unavailable controls reflect capabilities reported by the device's driver. A disabled control does not necessarily mean that the hardware lacks a feature; the driver may not expose it.

Safe preview: launch with piper-kirigami --mock to use simulated devices. Demo mode never contacts hardware. The “Capability test mouse” exists to exercise features that the G600 does not support. Launch without --mock to use the real system service; there is no silent fallback to demo devices.

2. Save, Apply, Reset and Defaults

Editing controls changes a local draft. What Apply and Reset cover depends on the page:

  • Individual assignment page: Apply submits only the current assignment draft, for the displayed device, profile, layer and button. It does not submit unrelated sensitivity, lighting, profile or other button edits. Reset discards only this assignment's pending edits and restores its last known device state.
  • Buttons overview: Apply submits pending button assignments for only the selected profile, across both Normal and G-Shift layers. Revert discards that same group of assignment drafts. Neither action includes DPI, lighting, other settings or other profiles.
  • Sensitivity: Apply/Reset covers the selected profile's DPI stages and polling rate.
  • Lighting: Apply/Reset covers the selected profile's lighting zones.
  • Advanced: Apply/Reset covers the selected profile's angle snapping, debounce and polling rate. Polling rate is the same setting shown on Sensitivity.
  • Profiles: Apply/Reset covers the selected profile's supported name/enabled settings and active-profile selection on that device.
  • Defaults: automatic restoration is unavailable and this action is disabled. Reset does not restore factory settings and does not undo changes already applied.

Page actions leave unrelated drafts intact, including pending button assignments and edits in other profiles or devices. A profile activation changes which on-device profile is active, but does not apply its unrelated settings drafts.

Save lighting keeps lighting-editor changes in the lighting draft and closes that editor. It does not write to the mouse; use the Lighting page Apply afterward. Cancel closes the lighting editor without saving its current edits.

The assignment child page has its own Help, Reset, Defaults and Apply controls. Use Back to return to the overview. If you try to leave with an unapplied assignment draft, an unsaved-changes prompt lets you keep editing, discard that assignment's changes, or explicitly apply it and continue. Other pending drafts remain intact; navigation never silently applies them. Review the scope in the current page before pressing Apply.

Settings drafts can remain while you move between settings pages or profiles; each page applies only its stated scope. Closing with pending changes requires a discard decision. In real mode, Apply can alter physical mouse settings and button behavior.

Write completion: ratbagd's commit is asynchronous. A submission message means that the request was handed to ratbagd, not that firmware persistence was independently verified. The application reports daemon errors, including delayed resynchronization failures. A failed write may have partially changed daemon or device state; follow the error guidance before discarding edits. Keep a way to recover mouse input when experimenting with essential buttons.

3. Button assignments

  1. Open Buttons and choose Normal or G-Shift when the device has layers.
  2. Select a numbered target on the mouse diagram. Its assignment is highlighted and scrolled into view in the list.
  3. Open that assignment from its row or edit control. When the diagram has keyboard focus, Enter opens the selected assignment.
  4. The individual assignment opens as a child settings page inside the main window. Check its device, profile, layer and button, then choose an action and fill its fields.
  5. Use the child page's Apply to submit only that assignment. Use Back to return to Buttons; an unapplied draft triggers a navigation prompt.

Assignment page: Help, Reset, Defaults and Apply

Help and F1 open the topic for the selected assignment type. Reset discards only this page's current draft. Defaults is unavailable because automatic restoration is not supported. Apply sends only the current assignment to ratbagd; it does not submit unrelated general settings drafts. The Buttons overview has its own broader Apply/Revert scope: the selected profile's pending button assignments in both layers. It still excludes DPI, lighting and other profiles.

Changing fields alone does not write to hardware. Review the target before Apply, particularly for essential click buttons. The page retains errors when validation or submission fails. After a partial write, follow the error guidance rather than assuming Reset can roll back hardware. Choosing Back, another setting, device, profile or assignment while this page has unsaved work asks how to handle that draft.

You can also use the quick-record action directly in an overview row. Press the shortcut, then choose Stop recording to stage a valid recording for that assignment. Recording stages a pending assignment; it never writes automatically. Cancel discards the current recording. Finish or cancel before changing the layer, page, device or profile.

On the overview, clicking Help stops capture so handbook keys are not recorded. For an interrupted overview recording, return and choose Use shortcut to stage it, or Cancel to discard it. Review the selected profile and layer, then use the overview Apply to submit that profile's pending button assignments. Revert discards that profile's pending assignment drafts. For the full set of action fields, open the assignment child page.

Available action types come from the selected device:

  • Mouse button
  • Keyboard key
  • Special action
  • Macro
  • Disabled

Mouse-button assignment

Choose Mouse button, then click its current value to open the searchable mouse-button list. Select the number to send when this physical control is pressed, then choose OK to keep it in the assignment draft. Numbers refer to mouse-button actions, not keyboard keycodes or diagram indices. The G600 driver accepts mouse actions 1–5; other devices may expose a different supported range.

Apply submits only this assignment. Reset restores this assignment's draft. See assignment page actions and write scope.

Keyboard-key assignment

Choose Keyboard key, then click its current value to open the complete searchable list available for this assignment. Search by name or numeric Linux evdev keycode, then select a result and choose OK. A keycode identifies the physical key event; it is not a Unicode value or a typed character. For a chord such as Ctrl+C, select Macro instead.

In a value picker, use the search field to filter by name or number, then select a result with the mouse or Up/Down keys. The current value is marked. Enter confirms a valid selection, like OK. Selection remains local to the popup until you choose OK; OK is unavailable without a valid selection. Cancel, Escape or closing the popup leaves the assignment draft unchanged. Keeping a value with OK still requires the assignment page's Apply to submit it.

Apply submits only this assignment. Reset restores this assignment's draft. See assignment page actions and write scope.

Special-action assignment

Choose Special action and select one of the driver's supported functions, such as DPI or profile control or a second-mode action. The list is capability-filtered; unsupported device functions cannot be enabled through this control. The Default DPI action selects the DPI stage marked Default on Sensitivity; it does not reset factory settings.

Apply submits only this assignment. Reset restores this assignment's draft. See assignment page actions and write scope.

Macro assignment

Choose Macro / key combination and use the visual event editor to build or change the sequence. These edits change only the current assignment's local draft; review the events before Apply.

The visual Events panel is always visible for this assignment type. Each numbered row displays its event type and value together. Devices with unrestricted macro support also offer Delay events. Add, remove or reorder rows; incomplete or unsupported sequences keep Apply disabled.

The G600 accepts one non-modifier key with modifiers, not arbitrary timed or multi-key sequences. See recording and event-editor details for event types and an example.

Apply submits only this assignment. Reset restores this assignment's draft. See assignment page actions and write scope.

Disabled assignment

Choose Disabled to assign no action to this physical control in the selected profile and layer. There are no additional action fields. Disabling an essential click button can make the mouse difficult to use, so review the target and keep a way to recover input.

Apply submits only this assignment. Reset restores this assignment's draft. See assignment page actions and write scope.

4. G600 and G-Shift

For the Logitech G600, choose Normal or G-Shift assignments using the tabs above the diagram and assignment list. The same physical mouse diagram is used for both layers.

The layer selector is view-only. It does not hold G-Shift, enable G-Shift on the mouse, activate a hardware profile, or create pending changes. It chooses which layer you inspect and edit. Editing an assignment in that layer is a separate operation, and still requires Apply.

The G600 driver exposes twenty normal assignments and twenty shifted assignments. Its reserved internal index 20 is excluded; shifted assignments use indices 21–40. Display labels identify physical controls rather than asking you to work with these raw indices.

The G600 supports mouse actions 1–5 and a restricted set of special actions. Its shortcut support is a single non-modifier key with modifier keys. Arbitrary timed or multi-key sequences are rejected. Profile rename/disable, stage disable, independent X/Y sensitivity and LED brightness are unavailable when the driver does not support them.

5. Keyboard shortcuts and macros

Choose Macro / key combination on the assignment child page to edit its sequence visually. The event editor changes only this assignment's local draft; review it before Apply.

To record a shortcut instead, use the quick-record action in a Buttons overview row, then choose Stop recording to stage it. Recording receives application keyboard events; it is not a system-wide recorder. While capture is active, application shortcuts such as F1 and Ctrl+F are recorded. Clicking Help stops capture and leaves the choice to Use shortcut or Cancel.

The Events panel shows the sequence as numbered rows whenever Macro / key combination is selected:

  • Add…: use the action in the Events header. In the popup, choose Key down or Key up and select a key from the searchable list. Choose OK to insert that one event. Selecting a key alone inserts nothing. Cancel, Escape or closing the popup inserts nothing; a matching release event is not added automatically.
  • Replace: existing events have fixed types and values. Remove an event and add a replacement to change its key, event type or delay. On supported devices, choose Delay in the Add… popup, set milliseconds and confirm with OK.
  • Reorder: use the up/down controls to move a row one place.
  • Remove: use the row's remove control to delete that event from the draft.

Events run from top to bottom. Pair every Key down with a matching Key up. For Ctrl+C, use four rows in this order: Key down Left Control, Key down C, Key up C, Key up Left Control. Recording that chord with the overview quick recorder creates these events for you.

Device limits: the G600 accepts one non-modifier key with modifiers. Place the chord's Key down events before its Key up events, with the main key released before its modifiers. Its event editor offers Key down and Key up only; delays and arbitrary multi-key sequences are unavailable. Devices with unrestricted macro support also offer Delay, with a duration from 1 to 60,000 milliseconds.

The event editor changes only the local draft. Apply stays disabled while a sequence is incomplete, unbalanced or unsupported; read the validation message and correct the rows. Removing a row may temporarily leave an incomplete sequence. Apply still affects only this assignment.

The overview quick recorder supports common letters, numbers, modifiers, navigation keys and F1–F12. If a key cannot be recorded, no partial shortcut is accepted. Choose a supported key in the event editor or record another shortcut. A new recording clears the previous recording error.

6. Sensitivity and DPI stages

Each DPI stage stores one supported sensitivity value, or separate X and Y values when the device supports independent axes. Higher DPI produces more pointer movement for the same physical travel. Choose from the values supplied by the driver.

  • Enabled: include the stage when cycling sensitivity. Devices that keep every stage enabled show this as unavailable.
  • Active: the currently selected DPI stage. Choosing a different stage is a pending change until Apply.
  • Default: the stage used by the Default DPI button action. It does not mean restoring factory defaults.

Polling rate, in hertz, controls how often the device reports input. Only supported rates are offered. The polling-rate control on Advanced edits the same setting. The application does not benchmark latency or recommend a particular rate for your computer.

7. Lighting

Open Lighting and click a lighting zone in the diagram or list. Unlike button diagram selection, selecting a lighting target opens its editor directly.

  • Effect: choose from the supported effects, such as Off, Solid, Cycle or Breathing.
  • Color: enter a six-digit RGB value in #RRGGBB form, for example #00aaff. The swatch previews that value.
  • Brightness: adjust the level if the driver supports it.
  • Effect duration: specify milliseconds for effects that use timing. Its visible effect depends on the selected mode and device.

Unsupported color or brightness controls are disabled. Save lighting keeps the draft; Apply sends it to ratbagd. The on-screen swatch is not evidence that the physical LEDs changed.

8. On-device profiles

The Profile menu chooses which existing on-device ratbagd slot you are editing. This is distinct from making that profile active on the mouse.

On the Profiles page:

  • Name: edit the name where renaming is supported.
  • Enabled: include or exclude a profile where supported. An active profile cannot be disabled; activate another enabled profile first.
  • Make active: stage the selected profile as the active hardware profile. Use Apply to submit that change.

No saved-profile library: this release manages only the device's existing slots. It does not create a separate collection of profiles on disk, import or export profiles, copy them between devices, or integrate with the separate JamesOS saved-profile library. Closing the app discards unapplied local drafts rather than saving them as reusable profiles.

9. Advanced settings

  • Angle snapping: driver-supported correction that can make near-straight pointer movement straighter. It may be unsuitable when you want uncorrected movement.
  • Debounce time: the supported interval, in milliseconds, used to filter repeated switch transitions. Available values come from the driver.
  • Polling rate: the same profile setting shown on Sensitivity.

Unavailable settings show an explanation. Changing these controls creates a draft and does not bypass Apply.

10. Search, navigation and keyboard controls

The top-left search field finds settings sections and button assignments in the selected device/profile. Search terms can include a physical button label, its assigned action, or Normal/G-Shift. Matching assignments appear beneath Buttons. Results stay visible until you clear or change the query.

Activating an assignment result switches to the appropriate layer, selects its physical button and reveals its row. It does not change that assignment. In the search field, use Up/Down to select a result and Enter to activate it.

  • Ctrl+F in the main window: focus the settings search.
  • Tab / Shift+Tab: move between controls. Arrow keys navigate controls such as lists and combo boxes.
  • Enter on the focused mouse diagram: open the selected assignment.
  • Alt+Left on an assignment page: go Back, with an unsaved-draft prompt when needed. Escape does not navigate away from that page; it dismisses an open value picker without changing the draft.
  • Ctrl+Enter: use the Apply action for the current editing scope when available. On an assignment page, this covers only that assignment. On Buttons overview, Apply covers the selected profile's pending button assignments in both layers.
  • F1 / Help: outside shortcut recording, open the authored help topic matching the current settings page or assignment type. Contextual Help is available only when a matching topic exists. The application menu provides Piper Kirigami Handbook for general reading.
  • Ctrl+F in the handbook: focus its text search; Enter or F3 finds the next match and Shift+F3 finds the previous match.
  • Esc in the handbook: close the handbook and return to the application.

The application menu also provides device refresh and Breeze Light/Breeze Dark. The handbook uses native Qt controls and the application's palette.

11. Troubleshooting

No connected device or service error

Check that the mouse is connected and supported by your installed libratbag version. ratbagd runs on the host, outside the Flatpak. It must expose org.freedesktop.ratbag1 on the system D-Bus and use API version 2. An administrator may need to check installation, service state and device permissions. The frontend does not install or start the service for you, request root access, or access raw HID/input devices itself.

Once the service or connection is corrected, use Refresh devices from the menu or the empty-state Refresh button. The menu action is disabled while there are pending edits or a write is in progress. Decide whether to apply or reset pending changes first. Do not use refresh as a substitute for saving drafts.

A setting is disabled

Read the nearby capability explanation and confirm the selected device and profile. The simulated capability-test device demonstrates controls that may be unavailable on a real mouse. A missing feature requires driver support; changing frontend values cannot create that support.

Apply failed or the mouse disconnected

Read the error before retrying. The application may have submitted only some changes. Reset can be blocked after a partial real write to avoid presenting a false rollback. Retry Apply when appropriate, or unplug and reconnect the device as the error suggests before discarding edits. After reconnecting, inspect the actual state reported by ratbagd. Already committed settings may persist after reconnecting.

Changes disappeared after restarting

Changing assignment fields creates only a local draft; the child page Apply submits that assignment. Save lighting keeps a lighting draft that needs the Lighting page Apply. If a submitted setting later reverts, report the device, driver and reproducible steps; this application does not independently verify firmware persistence.

Macro or color rejected

Use a valid #RRGGBB color. Check the event types, selected keys and balanced Key down/Key up rows in the macro event editor. G600 shortcuts must stay within its single-key-plus-modifiers restriction.

The app fails before opening

Native packages need matching Qt, PySide6, Kirigami and KDE desktop-style libraries. Arbitrary pip Qt wheels can be incompatible with distribution QML plugins. Prefer a matched distribution package set or a tested Flatpak build. The development app requires Breeze style, icons and color schemes. Include the error message and package/runtime versions in a bug report.

12. Flatpak and KDE integration

The development Flatpak ID is io.github.jheinem1.PiperKirigami. It talks to the host's ratbagd service using a specific D-Bus permission. It does not bundle a daemon and does not require direct raw-device access.

This offline handbook is installed inside the application and displayed by native Qt widgets, with the standard F1 help shortcut. It needs no web service, WebEngine, home-directory access or extra Flatpak permission.

KHelpCenter: this release does not register a DocBook handbook with KDE Help Center. The native in-app handbook works both in the sandbox and with distribution packages. Direct host KHelpCenter integration would need additional packaging and tested document discovery; it is not implied by the F1 shortcut.

Public support links, when clicked, open through the desktop's browser handler. They need an available browser/portal and network connection in that browser; they are optional and are not required to read the handbook.

13. Limitations, support and licensing

This preview is English-only. Full screen-reader accessibility, real Wayland/X11 integration, live desktop theme changes, physical mouse behavior, RGB output and firmware persistence need further testing. Automated fixture and D-Bus tests are useful protocol/UI checks, not hardware certification.

For a useful bug report include the app version or source commit, distribution, Flatpak/runtime or native package versions, mouse model, ratbagd version, selected profile/layer, the steps to reproduce, expected behavior and the exact error. State whether you were in mock or real mode. Review logs and screenshots for private information before sharing.
